绿色箭头为参考速度，蓝色为实际速度，1 米箭长对应 1 m/s。相机没有每步跟随锁定。每次仿真循环按 20 ms 限速；渲染负载高时仿真可能慢于实时。

## 持续按键归零修复

原生 WebRTC 按键不保证发送 repeat 事件，旧逻辑会因 0.4 秒没有事件而清零。现在每个控制循环通过 `carb.input.get_keyboard_value` 查询设备按下状态，只有实际仍按下才续期；设备查询失败仍沿用超时保护。确认键仍按下时，渲染卡顿导致的续期延迟也不再重置参考速度。松键继续按 4 m/s² 制动，急停不会被旧按键状态重新启动。浏览器 HTTP 桥接的心跳与超时逻辑保持原样。

专项回归覆盖无 repeat 持续按键、达到 2 m/s 后保持、松键制动、单轴释放、设备查询失败、急停、输入源隔离和渲染卡顿，见 `test_held_keyboard.py`。
