# MuJoCo 倒立后腿抽搐排查

## 结论与范围

当前主要问题与倒立显式电机反馈在 5 ms 步长下的数值/接触不稳定有关，已有三组对照支持。后腿腾空折叠时先出现较强振荡，随后发生后轮与同侧髋部自碰撞、膝关节小幅越限，并触发原倒立保护。不能仅凭这些实验完全排除策略对初始状态或模型误差的敏感性，但优先应修正本地积分和电机更新，再评估是否需要训练调整。

本次只增加诊断脚本与日志。没有修改正式 H/返回适配器、模型、训练参数、碰撞参数、正式步长或服务器训练任务。倒立仍加载 `teacher_4179.pt`；移动仍为 step 10474 / wheel 3824。

## 对照实验

环境：`E:/miniconda/envs/mujoco/python.exe`，MuJoCo 3.3.2。每组使用同一策略、参考轨迹、PD 增益、力矩与目标变化率上限，初始操作相同。

诊断脚本 `diagnose_handstand.py` 的 `--fine` 仅在当前进程内令 H 使用既有的 1 ms 电机/物理细分路径：策略仍为 50 Hz，接触历史仍每个外层 5 ms 更新。原 H 的子步计数检查在适配器入口按四次外层更新记账，实际电机更新为每个策略周期 20 次。没有把新设置写回正式程序。

## 碰撞与限位核查

- 机器人碰撞几何均处于有效碰撞位，未发现关闭碰撞或显式排除全部自碰撞的设置。显示网格与碰撞几何分别存在，显示网格本身不参与碰撞。
- 在原设置的高速振荡样本中检测到 `RL_hip / RL_wheel_link`、`RR_hip / RR_wheel_link` 接触，后轮确实撞到同侧髋部。
- 静止原设置的左后膝实际位置最大越过关节边界约 0.0303 rad；W 后 H 的左后膝越界约 0.0444 rad。目标仍按软限位和 8 rad/s 目标变化率处理，实测相邻策略周期目标变化不超过约 0.16 rad，没有发现越过该目标速率限制的瞬间目标跳变。
- 原设置记录的最大接触穿透约 2.8–3.8 mm。日志没有证明发生整条腿直接穿过机身；观察到的大幅视觉穿模还需结合显示网格与碰撞近似判断。
- 1 ms 对照仍记录小量限位超调（左后膝约 0.014–0.019 rad）和毫米级接触穿透，故不能宣称其已彻底消除全部越限或穿透。

## 为什么会倒地

代码中的腿部阻尼是 Python 计算的显式力矩反馈 `70*(target-q) + 2.5*(target_velocity-dq)`，不是模型内的关节阻尼；模型后腿关节阻尼和附加转子惯量均为零。`implicitfast` 不会自动识别 Python 已计算好的控制输入内部的反馈关系。上述对照与显式反馈在该姿态/接触条件下的步长敏感性一致。

MuJoCo 官方说明不同积分方法通过解析力导数处理速度相关力，其执行器力可以由增益/偏置项表达。因此若后续改为内置隐式驱动，也必须显式建模反馈，而不能只依赖积分器名称：[MuJoCo 3.3.2 数值积分与执行器力](https://mujoco.readthedocs.io/en/3.3.2/computation/#numerical-integration)。此处“外部反馈没有被自动隐式化”是结合本地代码作出的判断。

原倒立保护中的 `bad_contact` 在三次失败时达到约 658、1455、1606 N，持续约 0.08 s，触发终止。随后交互模式清除活动策略，但保留原电机上下文并停止策略更新；机器人已不稳定，也不再获得完整的逐帧倒立纠正，故继续倒下。该后续控制行为会让抽搐与倒地看起来连在一起。

## 修复优先级

1. 优先只对本地 H 引入 1 ms 电机/物理更新，保持策略 50 Hz、原权重、增益、轨迹和训练任务不变；正式落地前补测倒立保持、H 返回、重复进入以及不同朝向。
2. 检查接近限位时的实际超调和后轮—髋部间隙，评估是否需要更准确的碰撞几何或执行器数值表达。先不抬高速度上限，也不通过关闭碰撞掩盖问题。
3. 积分问题稳定后，再评价新倒立策略是否仍需扩大初始状态与后腿避碰覆盖。本次没有证据表明只靠追加 PPO 训练就能解决当前问题。
