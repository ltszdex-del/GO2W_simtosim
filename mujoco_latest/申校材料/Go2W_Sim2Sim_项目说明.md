# Go2-W 轮足机器人强化学习控制与跨仿真验证

**项目类型：** 个人机器人控制项目  
**技术栈：** Python、PyTorch、PPO、DAgger 策略蒸馏、Isaac Sim / Isaac Lab、MuJoCo、GLFW  
**版本范围：** Isaac Sim 训练 → 本地 MuJoCo 验证；资料整理日期为 2026 年 11 月 12 日。

## 1. 项目概述

本项目以宇树 Go2-W 轮足机器人为对象，构建基于强化学习的多动作控制系统，并将 Isaac Sim / PhysX 中训练的策略迁移到 MuJoCo 中进行连续交互验证。机器人具有 12 个腿部关节和 4 个轮关节，控制任务包括抬腿行走、轮式移动、站立保持、卧倒、起立、倒立及倒立返回。

项目重点是训练策略进入另一物理引擎后能否维持合理的动力学行为，以及不同策略能否在连续物理状态下衔接。为此，围绕机器人模型、观测与动作接口、执行器控制、数值积分和策略切换，完成了本地仿真适配、问题定位、修复与回归验证。

可用于申请材料的一句话介绍：

> 基于 PPO 构建轮足机器人多动作控制系统，将 Isaac Sim 训练策略迁移至 MuJoCo，并通过控制接口对齐、局部高频积分与状态机设计，改善跨仿真部署中的关节振荡和动作衔接问题。

## 2. 研究与工程问题

### 跨物理引擎的策略一致性

Isaac Sim 与 MuJoCo 对接触、执行器阻尼和数值求解的处理不同。相同的网络权重与控制增益，迁移后仍可能出现关节振荡、轮地接触异常和姿态失稳。因此，模型文件转换只是迁移工作的起点，还需对齐观测、动作和实际执行过程。

### 多个独立策略的连续衔接

单项策略通常从规定的初始姿态训练，交互运行时却会接收到运动后的残余速度、不同朝向以及上一个控制器留下的关节目标。停车、卧倒、起立和倒立返回等衔接环节，需要同时处理状态判定、控制上下文和历史观测，不能假定每次都从 reset 状态开始。

### 把问题定位转化为可验证的修改

针对不稳定现象，需要区分策略本身的问题、输入分布变化、控制接口错误及数值积分误差。项目通过对照实验和结构化日志，记录关节速度、接触、姿态、控制频率和模式切换，判断修复是否有效。

## 3. 技术方案

### 3.1 强化学习与动作设计

- 使用基于 PyTorch 的 PPO 训练模块，包含 GAE、策略裁剪、价值函数训练、熵正则和梯度裁剪。移动策略采用非对称 Actor–Critic：Actor 使用部署观测及其历史，Critic 可使用仿真中的速度、接触等额外信息。
- 抬腿移动输出腿部位置偏移，通过参考步态相位与奖励引导抬足、落足和速度跟踪；轮驱策略联合输出腿部位置偏移与四轮速度，使腿部能够参与重心和支撑调整。
- 针对左右转向差异，使用沿机身左右镜像的观测/动作映射、对称一致性损失，以及推理时的镜像平均。
- 训练任务覆盖前进、后退、原地旋转、移动叠加转向、指令释放与反向输入；奖励结合速度跟踪、支撑范围、接地、姿态、足间距、制动和关节平稳性。

上述方法建立在标准 PPO、参考模仿与对称性约束的基础上。项目贡献集中在任务设计、控制集成、实验迭代和跨仿真适配。

### 3.2 MuJoCo 模型与状态适配

从 URDF 构建 MuJoCo 机器人模型，保留质量、惯量、关节关系与碰撞结构；当前生成模型总质量约为 19.523 kg。对原 USD 场景中的 19 个碰撞体进行转换，对非凸台阶和坡面做凸分解并检查体积一致性。

通过状态与执行器适配层，把 MuJoCo 数据映射到原控制器所需的接口，明确关节顺序、四元数顺序、身体/世界坐标系、重力投影、单位缩放、历史观测和上一时刻动作。加载策略时检查权重、训练源文件、机器人资产及参考动作的接口和哈希，降低版本错配风险。

腿部通过位置目标与显式 PD 力矩控制，轮部通过速度执行器控制，并保留目标变化率和力矩限制。正常动作执行依赖物理积分；不通过写入身体或关节状态生成动作。

### 3.3 分频控制与数值稳定性

策略按 50 Hz 更新，常规移动的电机/物理更新为 200 Hz。针对站立、卧倒、起立和倒立中出现的振荡，在对应模式内将每个 5 ms 外层周期细分为五次 1 ms 电机计算与物理积分。

这一修改保留 50 Hz 策略更新与 200 Hz 接触历史采样，仅提高相关模式的内环更新频率。通过相同权重和增益下的对照测试，验证局部细分对振荡的影响，避免把所有失稳都归因于策略训练不足。

### 3.4 状态机与交互验证

集成七个策略入口，对应六份不同权重，其中站立保持复用起立策略。运动模式间通过状态机管理，处理关节目标、上一动作、历史窗口、朝向基准和电机控制上下文的交接。

停车由移动策略先制动；参考指令归零、实测水平速度和角速度进入阈值并持续 0.1 s 后，交给站立保持。新的移动输入可恢复移动控制。卧倒和起立进一步检查姿态、支撑、卸力与关节速度，改善连续动作之间的衔接。

使用独立 GLFW 查看器与本地控制面板进行键盘测试，显示参考/实际线速度、角速度及当前控制模式，同时提供无界面回归脚本和日志输出。

### 3.5 面向目标引擎的针对性策略蒸馏

倒立采用固定教师 4179 提供动作监督，学生使用 52 维本体观测的 50 帧历史及 57 维目标，共 2657 维输入。首次 DAgger 学生在 Isaac 中通过评估，进入 MuJoCo 后却约 4.88 s 失稳。同环境教师/学生对照发现前轮动作误差和支撑位置偏移；提高摩擦仍未解决问题。

在 MuJoCo 采集教师、混合动作和学生执行的 12 条轨迹，共 5552 个样本，在实际访问状态上查询原教师动作，覆盖失稳前状态。服务器继续进行 1000 次、2048 并行更新，每批混合 MuJoCo 固定数据和 PhysX 在线 DAgger，按动作阶段和困难状态分层采样，提高前轮等关键动作通道的权重，并约束前轮持续偏差。

补训学生通过六类连续倒立与返回回归后导入。固定留出轨迹的平均 MSE 未明显下降，闭环表现却改善，说明离线误差不能替代连续任务验收。本轮多项改动联合实施，未做逐项消融，不能将改善完全归于某一个权重或训练轮数。完整诊断、参数、证据与经验见 [倒立针对性蒸馏复盘](倒立针对性蒸馏复盘_20261112.md)。

## 4. 代表性问题与解决过程

| 问题 | 分析依据 | 采取的方法 |
|---|---|---|
| 站立抖动、倒立后后腿突然抽搐失稳 | 相同策略和增益下，5 ms 与 1 ms 的局部积分对照显示明显差异 | 对相关控制模式使用 1 ms 内环，保留策略更新频率和原保护 |
| Q/E 转向后进入倒立表现不同 | 教师训练初始朝向范围较窄，迁移后使用绝对世界朝向作为输入 | 将策略朝向观测改为相对进入倒立时的朝向，加回训练初始偏置；支撑几何仍使用真实世界朝向 |
| 停下后再次移动、卧倒或起立衔接异常 | 零指令不代表已经静止；不同策略的初始状态和内部上下文不一致 | 根据参考与实测运动状态交接，补齐控制上下文并重建历史观测 |
| 卧倒后一直无法进入卧姿完成状态 | 部分姿态中身体接近地面但未承重，控制器仍持续顶住；交互判定与训练终止条件混用 | 在适配层加入实际支撑与稳定判定，并在接近地面且稳定时平滑卸力 |
| 策略导入后接口不匹配或旧配置被重新覆盖 | 同维度模型也可能使用不同的观测顺序、参考轨迹或速度范围 | 使用接口 manifest、SHA256、独立部署记录和可重建的适配补丁管理版本 |
| 蒸馏学生在 Isaac 中通过，在 MuJoCo 中前轮漂移失稳 | 同环境教师正常；关键动作误差与部署状态分布偏移 | 用目标引擎状态的教师标注、混合在线 DAgger、分层回放及关键动作加权补训，以连续闭环回归验收 |

```text

├── run.py                         # 启动、策略执行循环、状态与速度显示

├── runtime/
│   ├── control.py                 # 控制状态机与策略切换
│   ├── commands.py                # 参考速度、加速度和制动积分

├── policies/                      # 权重、训练代码快照、部署记录
├── generated/                     # 生成的模型与转换报告
├── check_*.py                     # 连续动作与状态交接回归
├── logs/                          # 结果、诊断数据和验证记录
├── prepare_runtime.py             # 重建本地适配与已验证部署

```

## 7. 阶段边界与后续工作

本项目已形成可交互的 Sim-to-Sim 验证系统，并有针对连续动作和数值稳定性的有限场景记录。模型迁移、地形转换和场景加载已实现；尚未据此证明全地形运动能力、任意扰动鲁棒性或实机可部署性。

倒立针对性蒸馏已完成并导入，当前权重为 `policies/handstand_targeted_20261112/logs/targeted1000/student_999.pt`。服务器独立 256 并行、20 s 配对评估中教师与学生的成功/存活率均为 100%，本地六场景回归全部通过；结果限于对应初态、判据和测试时长。原训练完成后自动评估出现 inference tensor 重置异常，另启评估程序完成验证，原退出码 1 如实保留。

学生目标仍含足端/支撑锚点信息，需要里程计或状态估计；不能据此声称仅靠 IMU/编码器即可直接实机部署。本次没有完成真实传感器噪声、延迟和执行器模型标定。

进一步工作可围绕跨随机种子的统计评估、未见初始状态与外力扰动、传感器噪声及延迟、执行器模型标定和实机接口验证展开。

## 8. 申请材料的叙述重点

最有证据支持的主线是：**强化学习策略训练与集成 → 跨引擎动力学适配 → 对照实验定位振荡和状态分布问题 → 目标引擎数据驱动的针对性蒸馏 → 连续动作回归验证**。

简历适合保留三项贡献：多动作控制与迁移系统、稳定性问题的量化改善、无需 reset 的连续动作验证。训练轮数、版本编号和路径留在项目说明中；正式条目见同目录 `Go2W_简历项目条目_中英.md`。
